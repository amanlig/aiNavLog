## Electrical maintenance diagram implementation

components with online AI, review/match equipment and open linked maintenance
history. Full schematic editing and offline AI stay in the backlog.

Implemented Electrical-only diagram view with the example from Custom Marine
Products, JPEG/PNG add/update, manual equipment regions, AI scan review, common
component type choices (including LiFePO₄ batteries), model/serial fields and a
hover/tap modal with × close, latest Electrical service date/description and a
filtered service-history route. Unknowns can be assigned custom types or linked
to existing equipment. Identity matching proposes unique serial/name matches;
review remains required, and updates preserve equipment IDs and service history.

SQLite schema 3 stores equipment details, chunked diagram images and regions.
Migration retains existing telemetry/maintenance. Diagram/equipment saves are
atomic, stale base revisions are rejected, and exact retries are idempotent.
This requires replacement native builds; older schema-2 binaries cannot read the
upgraded database. No signed build or store delivery was launched in this work.

Added `diagram-ai-server/server.mjs`, a dependency-free Node 24 gateway using the
OpenAI Responses API, strict component output, server-only provider key, gateway
authentication, origin/size/rate limits and no image persistence/logging. Only the
diagram goes online; matching and maintenance records stay local. Owner asked how
the server would look, so SAD §5.6 now shows the device → HTTPS gateway → OpenAI
flow and user review → Rust → SQLite save path. Hosting/TLS and API key setup are
not yet configured. The screen-session token is not a multiuser login system.

Verification: UI typecheck/lint and 11 Node test files passed; local-storage tests
include schema migration, atomic rollback, persisted images/details, stale updates,
retry and retained history. Native maintenance ABI test and desktop-feature Rust
Clippy passed. Gateway HTTP/Responses-shape tests passed with stubbed OpenAI.
Browser integration passed with real temporary Rust/SQLite and explicitly stubbed
AI: image picker, example review, LiFePO₄ choice, modal/close, equipment-filtered

mobile layout. These results do not establish live AI accuracy or native-device
