## Responsibility refactor requested and implemented

Owner requested SAD §5.2 and implementation follow the clarified boundaries.
`data-model`, `data-capture` and `local-storage` are sibling Rust packages;
`native-integration` replaces the old nested native bridge and hosts desktop
composition/CLI/HTTP/replay. Device Interface retains BLE event handling and
protocol/receiver state and has no runtime SQLite/capture dependency.
`VictronMonitor<S: ObservationSink>` emits normalized metadata/observations to
`CaptureService` for validation and durable writes. Latest/history C queries call
Local data store directly. Existing schema/files/rows and ABI symbols are unchanged.
Staging, source references and implementation images are updated; the working
phone binaries predate this refactor and need replacement/regression. See
[ADR-0002](../decisions/0002-capture-storage-boundaries.md).

Refactor validation: tests pass for Local data store, Data capture, Device Interface
and native integration (desktop + mobile features); Clippy and the compiled C ABI
smoke check pass. UI typecheck/lint and all eight Node test files pass. An explicit
Cargo runtime dependency check confirms Device Interface has no SQLite/capture/
storage dependency. EAS staging of all sibling crates passes a locked/offline mobile
feature check. The real SQLite → relocated integration HTTP → history UI browser
regression passes. These checks do not compile Swift/Kotlin targets or replace
physical-phone acceptance. Existing desktop databases must be referenced by their
existing path when launching the CLI from its new package directory.
